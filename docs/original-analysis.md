# 원본 분석 — `kakao_sender/kakao_sender.py` (v5, 796줄)

원본은 "되긴 되는데 뭔가 잘 안 된다"는 상태로 전달받았다. 이 문서는 버전 v2 재설계의 **근거 자료**로, 원본의 구체적 결함과 우리가 무엇을 바꾸려는지를 정리한다.

## 요약

- **실사용 증상**: 이미지 업로드 도중 채팅창이 닫혀 전송이 잘림
- **운영 맥락**: 동아리 생일 축하 개인톡 발송 (약 161명 단톡방 중 본인 제외 160명)
- **실행 주체**: 요회별 담당자, 학기~1년 주기 교체, IT 비전문가
- **제약**: 생일자 본인이 단톡에서 보면 안 되므로 개인톡 필수

## 구조적 결함 3가지

### 1. 상태 추정이 "픽셀 한 점의 색"에 의존

```python
def is_chat_input_ready():
    px = get_kakao_pixel(0.5, 0.92)
    r, g, b = px
    return r > 200 and g > 200 and b > 200  # 흰색이면 준비됨
```

**왜 문제인가**
- 다크 모드에선 흰색이 아님 → 항상 False → `wait_until` 타임아웃 후 강제 진행
- Windows DPI 스케일링, 카톡 버전 업데이트로 상대좌표 92%가 의미 바뀜
- **이미지 업로드 중에도 하단 입력창은 이미 흰색 복귀 상태**라 True → "업로드 완료" 오판 → `Ctrl+W`가 너무 빨리 눌려 **전송 잘림** ← 실사용 증상의 정체

**v2 대응**: `uiautomation`으로 실제 컨트롤 객체·텍스트·상태를 질의. 이미지 업로드는 파일 크기 비례 대기 + UIA 말풍선 탐지 (Phase 2 결과에 따라).

### 2. 오발송 방지 메커니즘 전무

```python
pyautogui.press("enter")       # 검색 첫 결과 맹목 선택
pyautogui.hotkey("alt", "enter")  # 1:1 채팅 열기
```

**왜 문제인가**
- 검색 첫 결과가 동명이인·단톡방일 수 있음 (카톡은 채팅/친구/기타 결과가 섞여 나옴)
- 원저자 지침 "대화창이 아닌 **친구창**에서 해야 함" — 사용 전제가 있는데 프로그램이 검증하지 않음
- 한 명이라도 엉뚱한 대화방에 축하 메시지가 가면 **생일자 본인에게 유출**되는 재앙

**v2 대응**: 채팅창이 열린 후 창 제목(`win32gui.GetWindowText` 또는 UIA `Name`)과 타겟 이름을 비교. 불일치 시 즉시 `close_active_chat()` + 실패 기록. 친구 탭 강제 전환 (`switch_to_tab("친구")`).

### 3. 명단 경직

```python
MEMBERS_FILE = os.path.join(BASE_DIR, "members.json")
# 이름 문자열 리스트만 저장
```

**왜 문제인가**
- 담당자 교체 시 카톡에 저장된 이름이 달라짐 → 명단 전체 재편 필요
- 이름 변경·동명이인·탈퇴 추적 수단 없음
- 단톡 참여자 리스트는 카톡 PC에서 **복사 차단** → 매 발송 전 수작업 대조

**v2 대응**:
- 원본(CSV): `id`(UUID) · `name`(정식명) · `group`(요회) · `birthday` · `phone_last4`
- 매핑(JSON): `id → kakao_name` 로컬 파일. 담당자마다 별도
- 담당자 교체 시 원본 CSV는 공유·재사용, 매핑만 새로 작성

## 재활용한 것

원본에서 가져다 쓰는 요소들 (v2에서 그대로 유지):

- **색상 팔레트 `C = {...}`** → `kakao_sender.app.COLORS` (감성적 포인트)
- **`맑은 고딕` 폰트 + `F(size, bold)` 헬퍼** → 동일
- **이미지 → DIB → `CF_DIB` 클립보드** 트릭 → `engine.kakao._copy_image_to_clipboard`
- **`members.json` 구형 포맷 포용** → `load_members_from_legacy_json()`
